# Privacy boundary

No collection data, catalogs or artwork ship. Tests use Clockwork Turnip and Imaginary Orchard, invented solely for this repository. No private seed, database, export, configuration, history or deployment artifacts were read for extraction. No source runtime network calls, polling, external providers, authentication or cache migration are present. Dependency installation uses the npm registry as a development action only.

User-created cards, printings, copies and operation history persist in IndexedDB on this origin/profile/device. Browser clearing or eviction can remove them. No device sync or encrypted-vault claim is made. Keep a distinct hosting origin; the database namespace is community-collection-local. Settings exposes complete backup downloads and guarded restore. Pre-restore recovery copies are retained in a separate community-pre-restore-recovery IndexedDB database on the same origin. They are not uploaded or synchronized and remain vulnerable to browser clearing/eviction; download and keep backups outside the browser. Backup files contain manual notes and complete operation history, without encryption.

## Phase 3A (current behavior)

The pinned real metadata catalog is local-development-only and redistribution remains unapproved. Optional personal images are selected explicitly from a device and stored only in this browser's IndexedDB after metadata-stripping re-encoding. No artwork is bundled. There is no image server, remote URL input, search, download service, analytics, public gallery or sharing. Selecting a file does not grant redistribution rights. The acknowledgment is informational and does not certify ownership; stored rights remain unverified. Source filenames and original bytes are discarded; retained provenance contains the local timestamp, dimensions, acknowledgment and optional artwork-association notes.

Full .ncv backups and retained pre-restore recovery copies contain personal image bytes and private provenance without encryption. Downloading is an explicit local export; the app never sends it elsewhere. Browser clearing/eviction can lose inventory and media. Remove deletes live associations and unreferenced blobs, but does not erase prior downloaded or retained recovery backups. Retained recovery copies remain in the separate recovery database until browser-origin data is cleared. Keep complete backups somewhere safe. Metadata/trade exports do not preserve artwork. Desktop Chromium and a mobile-sized viewport are tested; actual mobile camera/library, Safari and Firefox behavior are not certified.

## Phase 3B storage and offline behavior (supersedes the initial extraction description)

The local-development build includes the pinned metadata catalog and original geometric app icons. A service worker fetches only same-origin build files to install a versioned application shell; it has no collection/image upload or runtime catalog service. CacheStorage holds app code and the development catalog; IndexedDB holds installed catalog records, inventory, processed personal artwork and recovery data. There is no analytics, external artwork provider or cloud synchronization. No public hosting is performed by this phase; future HTTPS hosting requires separate owner authorization.

Previously cached builds can open offline and edit inventory and images locally. First launch without a connection cannot load the application: its own UI is unavailable until successfully cached. The status UI reports caching, readiness and pending updates; readiness is not a guarantee against later browser eviction. Private browsing, restricted storage, OS pressure, browser clearing, uninstalling and origin changes can make data inaccessible or delete it. Persistence requests may be denied or unsupported. A grant is not a backup. Safari and installed PWA storage must be checked separately on the actual device.

Updates install a complete new app cache before becoming eligible to activate. They wait until every older controlled window closes. Finish writes, processing and downloads first. The app never forces a reload, calls skipWaiting, deletes IndexedDB, or clears inventory/images/recovery during app updates. Only older caches with this app's shell prefix are deleted at activation. Catalog installation retains its existing guarded additive/review behavior. Database schema remains version 3; app caches are not database migrations. Future schema changes must retain transactional upgrade and blocked-tab handling. Do not manually downgrade code against a newer schema.

Keep dated full `.ncv` files outside browser storage and periodically prove restoration into an empty separate test installation. Save app source/version and origin details with them. Files contain unencrypted catalog metadata, history, notes, media and provenance; protect their storage accordingly. Recovery copies on the same origin cannot protect against eviction or device loss. Never clear website data as an update or troubleshooting step before exporting and validating an external backup. See iphone-manual-checklist.md for the pending physical-device acceptance record.
