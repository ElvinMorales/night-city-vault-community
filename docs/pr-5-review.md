## Imported collections, filtering and collection safety

Exact ID plus consistent name succeeds; punctuation-normalized unique legacy name with different ID succeeds. Duplicate normalized names fail closed for name fallback; an exact consistent ID remains usable even if another source name is identical. Explicit conflicting/unrecognized color or primary type, conflicting known playset class, local/source review flags, absent catalog candidates, and contradictory ID/name records return Unknown. An unknown playset class or absent color/type supplies no contradictory evidence and may use a unique supported name. Additional type tags do not select a different identity; the primary type is the identity guard. This remains conservative heuristic matching, not proof that arbitrary custom cards with identical names represent the same game card. Renamed catalog identities may intentionally lose stats rather than receive a false match. Frozen synthetic legacy inputs verify read-only behavior. No personal imports were used.

Cost/PWR/RAM use exact string representations of integers and numerically sorted options. Unknown and zero remain distinct. Options are snapshot-wide; values absent from an edition deliberately yield no results rather than reset the selector. Eddies Any/Sellable/Non-sellable/Not listed behave independently and in conjunction. Browser expected results are calculated from catalog identities and eligible printings, with results deduplicated by gameplay card. Rarity and edition must match the same printing. Ownership is the existing aggregate gameplay-card ownership, including the pre-existing owned-outside-selected-edition discoverability rule. Grid/list share the same result set.

Clear browsing filters resets all eight facets together while retaining search, edition and ownership by design. Edition changes reset rarity but retain gameplay choices; Binder/Pack Desk navigation clears query, ownership and facets consistently, while edition/view/panel state persist. Filter toggle has a persistent aria-controls target, aria-expanded, and native hidden handling. Controls are labelled; collapsed controls disappear from the accessible group and keyboard path. Empty results are explicit. Counts represent matching gameplay identities before the existing 100-card pagination, not printing counts.

Reviewed the diff and call paths: no storage schema, migrations, collection commands, canonical identity, quantity, exact/unresolved printing, reservation/protection, allocation, location, activity, backup/restore, or photo logic changes. Filtering uses React state and derived maps only. The browser check records **zero readwrite transactions** and equality of every object store before/after opening, applying, clearing and changing browse filters. This starts after normal catalog installation; first-launch catalog installation is an existing intentional write and is not confused with filtering. Full storage/backup/photo suites additionally exercise populated synthetic collections.

Resolver and per-card derived maps are memoized by catalog/card arrays, not rebuilt on every filter change. Map lookups are constant-time; option enumeration over 151 rows is trivial. Existing large-collection scenarios exercise 140/500/1,000/5,000 imported identities with bounded rendering. The final local 5,000-identity scenario measured 4,753ms install/binder and 34ms search at 390×844; the bundled 151-card scenario measured 1,169ms install/binder and 34ms search.
